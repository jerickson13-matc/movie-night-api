# Team Charter & Ground Rules: Movie Night Voting API

## Project Purpose & Scope
* **What we are building:** A backend RESTful API in Java for our Movie Night Voting service. It will handle movies, watch parties, and votes, using Hibernate and a SQL database.
* **Why we are building it:** To serve as a shared, reusable backend service that our team members can plug into our individual projects for the course.
* **In-Scope:** Setting up entities, building Jersey endpoints, writing JUnit tests, writing JavaDoc, and deploying the app publicly to AWS.

## 2. Team Members & Responsibilities
* **Shared Ownership:** We’re splitting up the work across different components (database/Hibernate, controllers, testing, and deployment), but everyone will contribute code to the repository.
* **Full Understanding & Cross-Training:** To make sure everyone understands the entire application and can answer questions about it. We will hold quick code-walkthrough syncs before merging major features.

## 3. Communication Plan
* **Team Meetings:** We will meet regularly via MS Teams on a weekly schedule to check progress, assign tasks, and merge code. We’ll schedule extra check-ins right before major milestones or deadlines.
* **Daily Communication:** Outside of meetings, we’ll use our team chat channel for daily updates, questions, and quick syncs. Everyone is expected to check messages at least once a day.

## 4. Git, Branching, & Code Review Strategy
* **Branching Workflow:** 
  * The `main` branch will always stay clean, stable, and ready for deployment.
  * Everyone will work on separate feature branches.
* **Pull Requests:** No one merges directly into `main`. Every code change has to go through a Pull Request that requires at least one peer code review to check for bugs and make sure everything looks solid.

## 5. Support, Accountability, & Handling Blockers
* **Getting Help:** If someone gets stuck on a technical blocker, they should reach out in the team chat right away. We agree to respond and help each other out within 24 hours.
* **Missed Work & Deadlines:** If someone falls behind, they need to give the group a heads-up as soon as possible. If a team member goes completely unresponsive for 48 hours without notice, the rest of the team will step in to redistribute their tasks so the project stays on schedule, and we'll notify the professor.

## 6. Core Team Values & Conflict Resolution
* **Decision-Making:** We make big choices (like database schema design or endpoint structures) by consensus. If we're split, we'll choose the option that makes the most sense for maintainability and course requirements.
* **Conflict Resolution:** If disagreements happen, we will address them openly and professionally as early as possible. 
* **Code Feedback:** When doing pull request reviews, feedback will be constructive, objective, and focused strictly on the code.
* **Mutual Respect:** We respect each other's time, schedules, and outside commitments, and we will keep our workloads balanced fairly.
